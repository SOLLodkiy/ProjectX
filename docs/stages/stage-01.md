# Этап 01. Каркас и система модулей

## Что сделано

- Установлен SDK .NET 10.0.403 через winget с согласия пользователя; версия закреплена в `global.json`.
- Создано решение `ADHDWindows.slnx`: `ADHDWindows.Core`, `ADHDWindows.Platform`, `ADHDWindows.App`, `ADHDWindows.Modules.Sample`, `ADHDWindows.Tests`. Проект `ADHDWindows.Watchdog` появится на этапе 05.
- Core:
  - контракт модуля `IModule` и `IModuleContext`;
  - `ModuleLoader` и `ModuleHost`: загрузка и запуск модулей;
  - шина `EventBus`;
  - хранилище `JsonFileStore` для сохранений и настроек;
  - данные `GameData` и тексты `TextCatalog`;
  - журнал `FileLog`;
  - `GameHost`, который собирает ядро и управляет его жизненным циклом.
- Platform: защита от второго запуска `SingleInstanceGuard`.
- App: приложение без окон со значком в трее, меню «Выход», флаг `--dev` и запись необработанных ошибок в журнал.
- Sample: тестовый модуль считает запуски. Приложение на него не ссылается.
- Данные: `data/texts/ru.json`.
- Написано 40 автотестов.

## Ключевые решения

- **Подключение модуля.** Модуль лежит в `modules/<Имя>/<Имя>.dll`, каждый загружается в свой `AssemblyLoadContext`. Сборка Core всегда берётся у программы, иначе `IModule` из модуля и из ядра оказались бы разными типами.
- **Новый модуль без правки ядра.** Достаточно создать проект с именем `ADHDWindows.Modules.*` и добавить его в решение. `Directory.Build.props` подключает Core, `Directory.Build.targets` копирует сборку в `modules`, а приложение находит проект по маске только ради порядка сборки.
- **Изоляция ошибок.** Сбой сборки модуля, его запуска, остановки или подписчика на шине записывается в журнал и не затрагивает остальных.
- **Эффекты модуля.** Ядро само снимает подписки при остановке модуля, сохранения и настройки разделены префиксом `modules/<id>/`.
- **Сохранения.** Запись идёт через временный файл и `File.Replace` с копией `.bak`. Повреждённый файл не перезаписывается: он копируется в `.corrupt-*`, а данные берутся из `.bak`. Автосохранение раз в минуту, при выходе сохранение обязательно.
- **Шина синхронная**, подписчики вызываются в потоке отправителя.
- **Трей на WinForms `NotifyIcon`**: готовый компонент сам восстанавливает значок при перезапуске Проводника. Значок пока системный, свой появится на этапе 02.
- **Сборка self-contained** включена только для публикации (`PublishSelfContained`), чтобы обычная сборка оставалась быстрой.

## Проверка

- **Запуск и закрытие через трей: выполнено.** `ADHDWindows.exe --dev` запущен, значок и меню с «Режим разработчика» и «Выход» проверил пользователь вручную, потому что агенту недоступен правый клик по панели задач. После «Выход» значок исчез, процесса нет, в журнале есть «Ядро остановлено».
- **Тестовый модуль из `modules` без правки ядра: выполнено.** В журнале `Модуль запущен: sample`; тесты `ModuleTests` загружают его из файла при отсутствии ссылки на сборку.
- **Сохранение переживает перезапуск: выполнено.** Журнал показал запуски номер 1, 2 и 3: после выхода через трей и после принудительного завершения спустя 65 секунд, когда уже сработало автосохранение. Значение также проверено тестом `Sample_module_state_survives_a_restart`.
- **Тесты: выполнено.** `dotnet test`: 40 пройдено, 0 не пройдено. Сборка без предупреждений, предупреждения считаются ошибками.
- **Защита от второго запуска: выполнено.** Вторая копия завершилась с кодом 0, первая продолжила работу. Запуск после принудительного завершения прошёл без помех.
- **Флаг режима разработчика: выполнено.** Журнал показал `режим разработчика: True` с `--dev` и `False` без него.
- **Публикация self-contained: выполнено.** `dotnet publish src/ADHDWindows.App -c Release -r win-x64` собирается и содержит среду выполнения и `data`.
- В покое приложение занимало 55 МБ памяти при практически нулевой нагрузке на процессор.

## Незавершённое и известные проблемы

- `dotnet publish` не кладёт папку `modules` в результат: модули копируются только в `bin/<Конфигурация>/net10.0-windows`. Нужно решить на этапе 22 вместе с исключением тестового модуля из установки.
- Вторая копия закрывается молча, без сообщения пользователю.
- При принудительном завершении теряются изменения за последнюю минуту, до автосохранения.
- `schemaVersion` записывается в сохранения, но миграций пока нет.
- Отдельного отключения модуля нет, выключить можно только всю программу.
- В `%AppData%\ADHDWindows` остались журнал и сохранение от проверки. Они безвредны, значение `modules/sample/runs` равно 3.

## Что важно знать следующему этапу

- Команды запускаются из корня репозитория: `dotnet build ADHDWindows.slnx`, `dotnet test ADHDWindows.slnx --no-build`. Программа: `src/ADHDWindows.App/bin/Debug/net10.0-windows/ADHDWindows.exe`, флаг `--dev` включает режим разработчика.
- Перед сборкой закройте запущенную программу, иначе её файлы будут заняты.
- `ADHDWindows.App` собирается в `ADHDWindows.exe`. В `App` убраны неявные `using` для WinForms и `System.Drawing`, чтобы не было конфликтов имён с WPF; в файлах с WinForms они указываются явно.
- Для витрины компонентов уже есть `IModuleContext.DeveloperMode` и `AppOptions.DeveloperMode`, а тексты добавляются в `data/texts/ru.json`.
- `TrayIcon` использует `SystemIcons.Application` как временный значок.
- Контент читается по ключу-пути: `data/prices/sites.json` → `GameData.TryGet<T>("prices/sites", out var value)`. Комментарии и висячие запятые в JSON разрешены.
