# Этап 02. Дизайн-система и пиксельные ресурсы

## Что сделано

- **Палитра:** 20 именованных цветов в `assets/palette.json`.
- **Шрифты:** Galmuri9 для текста и Press Start 2P для заголовков, оба под SIL OFL 1.1. Лицензии лежат в `assets/fonts/licenses`, источники и команды описаны в `assets/README.md`.
- **Создание спрайтов:** исходники в текстовых файлах `assets/src/sprites/*.txt`. Инструмент `tools/ADHDWindows.AssetTool` собирает из них атлас и `assets/app.ico`, а также переводит TTF в растровый шрифт.
- **Спрайты:** 43 штуки, из них 25 рамок интерфейса, 17 иконок (монетка с 4 кадрами, замки, звезда, сердце, шестерёнка и другие) и сундук 32×32.
- **Core, `ADHDWindows.Core.Pixels`:** `Palette`, `SpriteSource`, `SpriteAtlasPacker`, `PixelFont` с измерением и переносом текста, `PixelScale`.
- **App, папка `Design`:**
  - основа: `PixelRoot`, `PixelSnap`, `PixelFrame`, `PixelImage`, `PixelText`, `PixelAssets`;
  - компоненты: `PixelWindow`, `PixelButton` трёх видов, панели, стили вкладок, списка и полосы прокрутки в `Pixel.xaml`, всплывающие уведомления `ToastCard` и `ToastManager` четырёх видов;
  - анимации `PixelAnimations`: тряска, вспышка, появление, исчезновение, въезд, вылет монетки;
  - витрина `ShowcaseContent` и `ShowcaseWindow`.
- **Запуск витрины:** пункт «Витрина компонентов» в меню трея в режиме разработчика или запуск с `--dev --showcase`.
- **Значок:** свой значок программы вместо системного, в файле приложения и в трее.
- **Platform:** `WindowTraits` делает окно неактивируемым, это нужно уведомлениям.
- Добавлен 41 автотест, всего их 81.

## Ключевые решения

- **Масштаб:** внутри `PixelRoot` размеры заданы в пикселях арта. Один пиксель арта занимает целое число пикселей экрана: `round(масштаб монитора × UiScale)`, по умолчанию `UiScale = 2`. При 100% это 2, при 125% и 150% — 3, при 200% — 4. В `app.manifest` включён PerMonitorV2, иначе Windows растягивает окно сама.
- **Текст рисуется геометрией, а не шрифтом WPF.** Каждый символ хранится как строки пикселей и выводится прямоугольниками с `EdgeMode.Aliased`, поэтому сглаживание невозможно и подойдёт любой цвет.
- **Привязка к сетке (`PixelSnap`).** Раскладка WPF даёт дробные координаты, например при центрировании. Каждый пиксельный элемент сдвигает рисунок к целому пикселю арта. Округление общее для родителя и детей, иначе они расходятся на пиксель. Пересчёт идёт после раскладки, потому что при первом рисовании родители ещё не на месте.
- **Строки в `ContentPresenter`** выводятся через общий `DataTemplate` для `string`, поэтому `Content="Текст"` сразу рисуется пиксельным шрифтом.
- **Цвет вкладки задаётся на её рамке.** Цвет самой `TabItem` наследовало бы содержимое вкладки.
- **Анимации ступенчатые:** значения меняются дискретно и на целое число пикселей, чтобы движение не размывало картинку.
- **Инструмент на C#, а не на Python.** Лишняя зависимость не нужна, а центры пикселей проверяются по контуру глифа, что не зависит от сглаживания.
- **Дизайн-система находится в `App`,** а тесты ссылаются на `App`, чтобы рисовать компоненты настоящим WPF.
- `WFO0003` отключён в `App`: это предупреждение WinForms о манифесте, а интерфейс здесь на WPF.

## Проверка

- **Чёткость на 100% и 150%: выполнено автотестом.** `PixelRenderTests` рисует все вкладки витрины, уведомления и центрированную кнопку настоящим WPF при 100%, 125%, 150% и 200%, задавая масштаб через `VisualTreeHelper.SetRootDpi`. Проверяется, что все цвета из палитры, а каждый пиксель арта — ровный квадрат. Тест нашёл и помог исправить три ошибки: привязку к пикселям экрана вместо сетки арта, запоздалую привязку и чёрный текст из стандартной темы.
- **Настоящее окно: проверено только на 125%.** Это текущий масштаб экрана, менять его агент не стал. Окно 1068×846 кратно 3, на снимках с экрана вкладок «Основы» и «Компоненты» 0 неровных пикселей из 858 168. На снимке вкладки «Движение» 3045 неровных пикселей: снимок сделан, когда поверх окна лежали уведомления с другим началом сетки, отдельно окно на этой вкладке не считалось. Глазами окно на снимке выглядит чётким.
- **Кириллица читается: выполнено.** Снимки просмотрены глазами. `AssetTests` подтверждает наличие всех русских букв и знаков в обоих шрифтах.
- **Компоненты: выполнено.** На настоящем окне через UI Automation переключены вкладки и нажаты кнопки. Показались три уведомления без потери фокуса, проигрались тряска, вспышка и монетка, полоса прокрутки отрисована. Прокрутка мышью и перетаскивание окна не проверялись.
- **Размер интерфейса:** ×1 и ×2 дали 0 неровных пикселей. При ×3 окно 1424×1128 выше экрана 1080 и обрезается снизу, поэтому 51 299 неровных пикселей на этом снимке не показательны: часть окна была за экраном. Эта кнопка есть только в витрине.
- **Сборка и тесты: выполнено.** `dotnet build` без предупреждений, `dotnet test`: 81 пройдено, 0 не пройдено.
- **Запуск:** ошибок в журнале после последних исправлений нет. Две записи об ошибках в журнале относятся к сбоям, уже исправленным на этом этапе.

### Что проверить вручную

1. Запустите `src/ADHDWindows.App/bin/Debug/net10.0-windows/ADHDWindows.exe --dev`.
2. В меню значка в трее выберите «Витрина компонентов». Значок должен быть пиксельной монеткой.
3. Посмотрите все вкладки: линии и буквы должны быть чёткими, без размытия.
4. В параметрах экрана Windows поставьте масштаб 100%, затем 150%. Окно должно перестроиться и остаться чётким.
5. Перетащите окно за заголовок, прокрутите список колёсиком и ползунком.

## Незавершённое и известные проблемы

- Необработанная ошибка в потоке интерфейса завершает программу: так настроено на этапе 01, ошибка записывается в журнал. Стоит решить до появления блокировок, на этапе 05.
- Модули ссылаются только на Core и не могут использовать компоненты из `App`. Если модулям понадобится свой интерфейс, дизайн-систему нужно вынести в отдельную библиотеку. Это правка структуры проекта, поэтому согласуйте её с пользователем.
- Поля ввода, флажков и выпадающих списков нет: они не входили в этап.
- Уведомления показываются только на основном экране.
- Настройки `UiScale` нет, значение задаётся в коде и меняется только в витрине.
- `PixelText` не виден специальным возможностям Windows. Кнопки передают имя сами, остальной текст нет.
- Шрифт `title` широкий: длинные заголовки стоит делать короткими.
- `tools/` не упомянут в разделе «Стек и архитектура» в `CLAUDE.md`, описание есть в `assets/README.md`.

## Что важно знать следующему этапу

- Любой пиксельный интерфейс должен лежать внутри `PixelRoot`, а размеры внутри него задаются целыми пикселями арта. `PixelWindow` создаёт корень сам. HUD не является обычным окном, поэтому ему нужен свой `PixelRoot`, образец есть в `ToastManager`.
- Подключение: `PixelAssets.Install` вызывается в `App.OnStartup`. Спрайт используется так: `<d:PixelImage Sprite="coin" />`, рамка так: `<d:PixelFrame Sprite="panel" />`, текст так: `<d:PixelText Text="{d:T ключ}" />`.
- Монетки: `PixelAnimations.FlyUp(canvas, "coin", точка)`. Уведомления: `ToastManager.Show(ToastKind.Reward, заголовок, текст, "coin")`.
- Цвета берутся из ресурсов `Brush.<имя>` через `DynamicResource`, это задел для тем этапа 18.
- `WindowTraits` в Platform подойдёт для HUD. Пропуск кликов добавляется туда же.
- Новый спрайт: допишите его в `assets/src/sprites/*.txt` и выполните команду из `assets/README.md`.
- В тестах WPF выполняется через `WpfThread.Run`. Переменная окружения `ADHDWINDOWS_SNAPSHOTS` сохраняет снимки `PixelRenderTests` в указанную папку.
- При запуске из bash не передавайте скрипты с кириллицей в PowerShell без BOM: они разбираются неверно.
