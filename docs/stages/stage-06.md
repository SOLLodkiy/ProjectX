# Этап 06. Блокировка программ

## Что сделано

- **Модуль `ADHDWindows.Modules.Locks`:** подключается как отдельная библиотека. Ядро о нём не знает, в `Core` добавлены только события `Locks/LockEvents.cs`.
  - `ProgramFile` читает данные файла и строит постоянный код программы.
  - `ProgramCatalog` загружает каталог, `ProgramClassifier` решает, бесплатна ли программа и сколько стоит.
  - `LockEngine` решает, что заморозить и когда отпустить. Windows подменяется через `IProgramSystem`, поэтому логика проверяется без настоящих процессов.
  - `UnlockLedger` хранит покупки с датой и ценой, `FreezeRestorer` размораживает после сбоя.
- **Каталог `data/locks/programs.json`:** 29 программ с ценами из идеи 004, цена по умолчанию 300, 24 записи всегда бесплатного, включая Claude.
- **Platform:** `ProcessControl` (сведения о процессах, заморозка), `WindowControl` (окна, в том числе приложения Магазина), `WindowWatcher` (события окон без внедрения в чужие процессы).
- **App:** `Locks/LockScreen` связывает модуль с окном, `Locks/LockScreenWindow` показывает экран покупки. В меню трея появился пункт «Заблокированные программы».
- **Тестовая программа `tests/ADHDWindows.TestApp`:** окно со счётчиком в памяти. Тесты замораживают только её.
- Добавлено 63 автотеста, всего их 287.

## Ключевые решения

- **Опознание идёт по данным внутри файла:** компания, продукт, исходное имя файла, пакет Магазина. Имя файла в каталоге не используется. Поэтому переименование не меняет ни цену, ни покупку, а файл `claude.exe` с чужими данными не становится бесплатным.
- **Постоянный код программы** строится из компании, продукта и исходного имени, без версии. Покупка переживает обновление. Для файла без сведений о версии используется хеш содержимого, и обновление такой программы потребует новой покупки.
- **Установщики** опознаются по описанию внутри файла. По имени `setup.exe` их определять нельзя, иначе переименование открывало бы любую программу.
- **Порядок блокировки:** свернуть окно, записать изменение в реестр, заморозить. Сворачивается заранее, потому что замороженная программа уже не ответит. Если запись не удалась, заморозки нет.
- **Одна запись на программу.** В ней все процессы и окна программы. Замораживаются все процессы с тем же кодом: у Discord и Steam это несколько процессов и разные файлы.
- **Заморозка через `NtSuspendProcess`.** Повторная разморозка ничего не ломает, поэтому требование к восстановителю выполнено. Перед действием сверяется время запуска процесса.
- **Развёртываются только те окна, которые свернул модуль.** Окно, свёрнутое пользователем, остаётся свёрнутым.
- **Нет прав — нет блокировки.** Процессы с повышенными правами и защищённые не трогаются.
- **Без каталога модуль не запускается.** Иначе неизвестно, что бесплатно, и Claude мог бы оказаться заблокированным.
- **Экран покупки не забирает фокус.** Человек мог печатать в другой программе, и случайный пробел не должен совершить покупку. Кнопки работают только мышью.
- **Один экран на все программы.** При первом запуске их может быть много, поэтому показывается список.
- **Каждые 3 секунды модуль осматривает окна.** События окон дают быструю реакцию, а осмотр подбирает потерянное и замечает закрытые программы.
- **В режиме разработчика блокировка выключена, пока не задана настройка `modules/locks/onlyUnder`.** Защита добавлена после случая из раздела «Проверка»: забытая или ошибочная настройка больше не заморозит настоящие программы.
- **Настройка `onlyUnder`** ограничивает блокировку одной папкой. Её используют все автотесты с настоящей программой.

## Проверка

- **Заблокированная программа замораживается и работает после покупки без потери данных: выполнено.** `Already_open_program_freezes_and_keeps_memory_after_purchase`: счётчик в памяти останавливается, окно свёрнуто, покупка нажимается настоящей кнопкой через автоматизацию Windows, счётчик продолжается с того же значения в том же процессе.
- **Покупка постоянна:** после перезапуска программа не замораживается.
- **Блокировка уже открытых программ при первом запуске: выполнено**, тот же тест. Программа, запущенная позже, блокируется тоже.
- **Переименование не обходит блокировку: выполнено.** Купленная программа под именем `totally-other.exe` остаётся открытой, а некупленная под именем `claude.exe` замораживается.
- **Claude, Проводник, Диспетчер задач и терминалы не блокируются: выполнено.** Настоящие файлы Windows проверяются в `Real_system_files_are_free`, данные Claude, браузеров и Windows Terminal в `Always_free_programs_are_recognized`. Claude и браузеры проверены на данных файлов этого компьютера. Окна консоли пропускаются отдельно.
- **Аварийная остановка размораживает всё: выполнено.** Горячая клавиша снимает заморозку и возвращает окно. Также проверены принудительное завершение программы, когда откат делает сторож, и обычный выход.
- **Сборка и тесты:** `dotnet build` без предупреждений, `dotnet test`: 287 пройдено, 0 не пройдено, три запуска подряд.
- **Живая проверка на этом компьютере:** настоящий Блокнот заблокирован по цене 50 при системном имени `NOTEPAD.EXE.MUI`. Калькулятор из Магазина заблокирован по цене 50 после разворачивания и отпущен сторожем. Экран покупки проверен на снимке, по нему исправлен тёмный текст на тёмном фоне.

### Случай при проверке

Скрипт живой проверки записал файл настроек в неверном формате. Программа не увидела ограничение и на 1 минуту 40 секунд свернула и заморозила настоящие Discord, Telegram, WhatsApp и Steam. Программа была завершена принудительно, сторож откатил всё: после этого 0 приостановленных потоков, все процессы отвечают, реестр изменений пуст. Данные не потеряны, потому что заморозка не трогает память. В режиме разработчика такая ошибка теперь приводит к выключенной блокировке.

### Что проверить вручную

Обычный запуск без `--dev` заблокирует все открытые платные программы: Discord, Telegram, WhatsApp, Steam и другие. Перед проверкой лучше сохранить работу и держать под рукой `Ctrl+Alt+Shift+Q`.

1. Запустите `src/ADHDWindows.App/bin/Debug/net10.0-windows/ADHDWindows.exe`.
2. Убедитесь, что открытые платные программы свернулись, а экран покупки показал их список. Claude, браузеры, Проводник и терминалы должны работать.
3. Нажмите «Позже», затем щёлкните замороженную программу на панели задач. **Это главное, что осталось проверить:** экран покупки должен открыться снова. Если нет, откройте его через пункт трея «Заблокированные программы».
4. Запустите от имени администратора любую платную программу. Она не должна заблокироваться.
5. Нажмите `Ctrl+Alt+Shift+Q`. Все программы должны ожить и развернуться.

## Незавершённое и известные проблемы

- **Щелчок по замороженному окну на панели задач живьём не проверен.** Логика проверена на подмене, но на настоящем окне система может не активировать его и не прислать событие. Попытка переключения через `SwitchToThisWindow` экран не открыла. Кнопки панели задач недоступны автоматизации, поэтому нужна ручная проверка из шага 3. Надёжные пути сейчас: пункт трея и повторный запуск программы.
- **Программы с одной копией.** Если замороженная программа сама не даёт запустить вторую копию, новый процесс может ждать её без окна, и экран покупки не откроется.
- **Заморозка приложения с глобальным хуком клавиатуры или мыши** может на короткое время замедлить ввод, пока система не снимет хук. На этапе 21 стоит это проверить.
- **Приложение Магазина, свёрнутое и приостановленное системой,** блокируется только при разворачивании: до этого его окно нельзя связать с процессом.
- **Вспомогательные процессы с другими данными файла** не замораживаются. Они продолжают работать в фоне, но окна программы заморожены.
- **Игры пока считаются неизвестными программами** с ценой 300, отдельная цена появится на этапе 07.
- **Экран покупки зависит от дизайн-системы.** Если её ресурсы не загрузились, покупка недоступна, но выход из программы всё размораживает.
- **Сведения о версии можно изменить** сторонним инструментом и так обойти блокировку. Защита от обхода входит в этап 21.
- Каталог проверен на данных файлов этого компьютера только для установленных программ. Условия для остальных записаны по известным значениям и будут уточняться на этапе 19.

## Что важно знать следующему этапу

- Новый вид блокировки добавляет значение в `LockKind` и переиспользует `LockOffer`, `LockOffersChanged`, `LockScreenRequested`, `UnlockRequested`, `ItemUnlocked` и окно покупки.
- `ProgramClassifier` вызывается для каждого процесса. Игры стоит опознавать до него или внутри него по папке библиотеки, раньше общего правила цены по умолчанию.
- Для Steam покупка лаунчера идёт через код `program:steam`. Правила из заметки 004 требуют, чтобы она не открывала игры, поэтому код игры должен быть отдельным.
- Настоящую программу в проверках можно запускать только с `--dev` и настройкой `modules/locks/onlyUnder`. Файл настроек имеет вид `{"schemaVersion":1,"values":{...}}`. Надёжнее всего писать его через `JsonFileStore`.
- `TestApp` принимает путь к файлу, куда пишет номер процесса и счётчик. Простой способ убедиться в заморозке: значение перестало расти.
- `ShowWindow` для замороженного окна блокирует вызывающего, можно использовать только `ShowWindowAsync`. Так же ведёт себя `SwitchToThisWindow`.
- Настоящая мышь приносит монетки и во время тестов, поэтому точное значение баланса в тестах с настоящей программой проверять нельзя.
