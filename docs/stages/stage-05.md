# Этап 05. Аварийная остановка и восстановление

## Что сделано

- **Core, `Safety`:** реестр изменений системы `ChangeJournal` (файл `recovery.json`), служба `RecoveryService`, контракты `ISystemChanges` и `ISystemRestorer`, разбор сочетаний клавиш `Hotkey`.
- **Контекст модуля:** новое свойство `Changes`. Восстановители модулей находит `ModuleLoader.LoadRestorers`.
- **`ADHDWindows.Watchdog`:** отдельный процесс в папке `watchdog` рядом с программой. Он держит горячую клавишу, следит за программой и откатывает то, что от неё осталось.
- **Platform:** `GlobalHotkey`, `WatchdogProcess` (запуск и перезапуск сторожа), `NamedSignal` (сигнал между процессами). Общая часть очереди сообщений вынесена из `MouseHook` в `NativeMessages`.
- **Откат выполняется в трёх местах:** сторож после завершения программы, ядро при обычном выходе и ядро при следующем запуске.
- **Трей:** показывает сочетание аварийной остановки. В режиме разработчика есть пункт «Тестовое изменение системы». Если клавиша занята или сторож не запустился, появляется уведомление.
- **Тестовое изменение:** модуль Sample записывает значение в свой раздел реестра Windows `HKCU\Software\ADHDWindowsRecoveryProbe`, а откатывает его собственным восстановителем. Ядро и сторож об этом разделе не знают.
- **Флаги разработчика:** `--user-dir=` задаёт отдельную папку данных, `--recovery-probe=` делает тестовое изменение при запуске.
- Добавлено 50 автотестов, всего их 224.

## Ключевые решения

- **Сначала запись, потом изменение.** `Record` сохраняет запись на диск до применения. Если запись не удалась, он выбрасывает ошибку, и применять изменение нельзя. Поэтому изменений, неизвестных реестру, не бывает.
- **Восстановитель должен быть безопасен при повторе.** Запись может остаться после отката, а откат может прийти к изменению, которое не успели применить. Контракт `ISystemRestorer` требует, чтобы оба случая ничего не ломали. Также реестр может вернуться к копии `.bak`.
- **Восстановители живут в сборках модулей, а не в ядре.** Сторож загружает их из папки `modules` так же, как программа. Новый вид изменения добавляется без правки ядра и сторожа. Сборки загружаются только когда есть что откатывать, поэтому неисправный модуль не мешает обычной работе сторожа.
- **Данные для отката — только строка.** Откатывать может другой процесс, в котором нет объектов модуля.
- **Горячая клавиша находится в стороже, а не в программе.** Поэтому она работает при зависшей программе. `RegisterHotKey` выбран вместо хука клавиатуры: система обрабатывает его сама, и он должен срабатывать при окнах с повышенными правами.
- **Порядок аварийной остановки.** Сторож посылает сигнал, программа сохраняет данные и закрывается штатно. Если за 3 секунды она не закрылась, сторож завершает её принудительно. После этого откатывает остаток. Сначала закрывается программа: иначе её модули могли бы снова применить изменения.
- **Аварийная остановка закрывает всю программу.** Так требует раздел «Безопасность для пользователя» в `CLAUDE.md`.
- **Запуски не мешают друг другу.** Каждая запись помечена идентификатором запуска, а сторож откатывает только свой запуск. Если новая копия успела стартовать, её изменения останутся нетронутыми. При запуске ядро откатывает всё, потому что другой живой копии в этот момент нет.
- **Файл реестра не держится в памяти.** Каждая операция читает его заново под именованной блокировкой, потому что пишут в него два процесса.
- **Запись удаляется после 5 неудачных откатов**, иначе одна и та же ошибка повторялась бы при каждом запуске. Данные записи попадают в журнал.
- **Сторож перезапускается** до 5 раз, если завершился раньше программы.
- **Проверка процесса по номеру и времени запуска:** система может выдать тот же номер другому процессу.
- **У сторожа отдельный файл журнала** `watchdog-ГГГГ-ММ-ДД.log`: два процесса не конкурируют за один файл.
- **Отдельная папка данных получает свою блокировку второго запуска.** Автотесты запускают настоящую программу и не трогают сохранение пользователя.

## Проверка

- **При принудительном завершении тестовое изменение откатывается: выполнено.** Настоящая программа завершена через `Stop-Process -Force`, значение исчезло из реестра Windows через 152 мс, сторож завершился, файл реестра пуст. Этот же сценарий проверяет тест `Killed_app_is_rolled_back_by_the_watchdog`.
- **Горячая клавиша работает при любом активном окне: выполнено, кроме окна с повышенными правами.** Основное сочетание `Ctrl+Alt+Shift+Q` отправлено при активном Яндекс.Браузере, программа вышла с кодом 0 через 316 мс, изменение снято. Окно с повышенными правами агент проверить не может, шаги ниже.
- **Зависшая программа:** тест приостанавливает процесс через `NtSuspendProcess`, нажимает клавишу, и сторож завершает программу и откатывает изменение.
- **Убиты и программа, и сторож:** изменение откатывается при следующем запуске.
- **Убит только сторож:** программа запускает нового.
- **Занятое сочетание:** `GlobalHotkey.Start` возвращает false.
- **Сборка и тесты:** `dotnet build` без предупреждений, `dotnet test`: 224 пройдено, 0 не пройдено, три запуска подряд. После них нет ни процессов программы, ни раздела реестра.
- **Потребление сторожа:** 5,4 МБ личной памяти, 20,5 МБ рабочего набора, 0,06 с процессора за всё время работы.

Значения журнала живого прогона:

| Сценарий | Результат |
| --- | --- |
| `Stop-Process -Force` | код завершения -1, откат 1 изменения за 135 мс после завершения |
| `Ctrl+Alt+Shift+Q` | штатный выход, сторожу откатывать нечего |

### Что проверить вручную

1. Запустите `src/ADHDWindows.App/bin/Debug/net10.0-windows/ADHDWindows.exe`.
2. Откройте Диспетчер задач: это окно с повышенными правами. Щёлкните по нему, чтобы оно стало активным.
3. Нажмите `Ctrl+Alt+Shift+Q`. Значок программы должен исчезнуть из трея, а HUD закрыться.
4. Запустите программу с `--dev`, выберите в трее «Тестовое изменение системы» и завершите `ADHDWindows.exe` в Диспетчере задач. Раздел `HKCU\Software\ADHDWindowsRecoveryProbe` должен исчезнуть. Проверить можно командой:

```bash
reg query "HKCU\Software\ADHDWindowsRecoveryProbe"
```

## Незавершённое и известные проблемы

- **Окно с повышенными правами живьём не проверено.** Шаги для пользователя указаны выше.
- **Клавишу можно поменять только в `settings.json`**, ключ `safety/hotkey`. Окна настроек пока нет, и новое значение применяется после перезапуска.
- **На защищённом экране клавиша не сработает:** запрос UAC и экран блокировки находятся на другом рабочем столе.
- **Если сторож не запустился или все 5 перезапусков исчерпаны**, аварийной клавиши нет. Пользователь видит уведомление только о неудачном запуске, а исчерпание перезапусков попадает лишь в журнал. Откат при следующем запуске при этом работает. На этапе 21 стоит решить, разрешать ли блокировки без сторожа.
- **Зависший восстановитель** остановит откат, тайм-аута у него нет. На этапе 21 стоит это проверить.
- **При принудительном завершении теряются монетки** с момента последнего автосохранения, то есть до минуты. Это касается только зависшей программы.
- **`dotnet publish` не кладёт в сборку папки `watchdog` и `modules`:** раскладка сейчас рассчитана на `dotnet build`. Это работа этапа 22.
- **Тесты оставляют папки `adhdwindows-tests-*` в `%TEMP%`**, потому что загруженная сборка модуля занята до конца процесса. Сейчас их 163. Это поведение прошлых этапов, вреда нет.

## Что важно знать следующему этапу

Порядок работы модуля, который меняет систему:

1. Создать класс `ISystemRestorer` в сборке модуля: открытый, с конструктором без параметров.
2. Вызвать `var mark = context.Changes.Record(вид, данные)` до изменения.
3. Применить изменение.
4. При снятии откатить изменение и вызвать `mark.Dispose()`. То же нужно сделать в `Stop()`.

Для заморозки процессов на этапе 06:

- В `data` нужно записать номер процесса и время его запуска: номер может достаться другому процессу, а откат выполняется после сбоя.
- `Restore` не должен завершаться ошибкой, если процесса уже нет.
- Модули ссылаются только на Core. Если восстановителю нужен код из `Platform`, сторож отдаст его сборку, потому что она лежит рядом с ним. Модулю нужна будет ссылка на этот проект.
- При большом числе изменений учитывайте, что каждая запись синхронно пишет файл на диск. Для пакетных изменений лучше одна запись на всю группу.
- `HudWindow` и другие окна не должны блокировать поток интерфейса дольше 3 секунд при выходе: иначе сторож завершит программу принудительно.
- Автотесты с настоящей программой удобно строить как `EmergencyStopTests`: `--dev --user-dir=` и сочетание клавиш из настроек.
